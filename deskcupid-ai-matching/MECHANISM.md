# 匹配机制

线上站点代码没改。报名数据从后台拉取后，在本目录做 DeepSeek 打分。

## 重复报名

`enrich.py` 在进模型之前删掉第一次：同一人只留 **createdAt 更晚** 的那一份。微信相同，或姓名相同但微信打错一个字符的，都算同一个人。

被丢弃的首报不会出现在 `pool.json` 的候选人卡里。

## 硬过滤（不消耗 token）

`prepare_pool.py` 在调用 API 之前丢掉：

- **异地**：城市桶不同（北京 / 上海 / 香港 / 海外各国等）。「未来回北京」算北京。
- **同班**：同一届同一班号（如 2016-07）。

剩下的才进 DeepSeek。姓名只留在 `idMap`，送给模型的卡只有代号 `M00` / `W00`；简介/理想型/看重里出现的真名也会被替换成代号。

## 怎么打分

对每个男生、每个女生各写一次谈恋爱 prompt（候选人多时按 8 人一批，避免 JSON 截断）。10 个线程并行调用 DeepSeek。

三次分（0–100），每次必须带中文理由：

1. 初见
2. 相处一个月
3. 认真长期

可调文案在 `DEEPSEEK_PROMPT.md`。男满意度 / 女满意度各取三次平均，和谐分是两边再平均。

## 两种结果

**局部最优**：每个人自己最满意的那一个。允许多人看上同一个人。

**全局最优**：匈牙利算法最大权匹配，只在已评分的合格对上分配。异地、同班格子不参与。
